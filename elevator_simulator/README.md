# סימולטור גרפי — תוספת לפרויקט

סימולטור של מעלית אחת בבניין קבוע של **10 קומות**. כל קוד התצוגה והחומרה
המדומה נמצא בתיקייה הזאת, בנפרד מחבילת `elevator_controller`.
הסימולטור משתמש בבקר הקיים ולא מממש אלגוריתם נסיעה נוסף.

## הפעלה

מתיקיית הפרויקט הראשית:

```powershell
py -m elevator_simulator
```

נדרשים Python 3.10 ומעלה ו-Tkinter, שכבר מותקן בסביבה הנוכחית.
לא נדרשות חבילות חיצוניות. יש להריץ מתוך סביבת שולחן עבודה.

## שימוש

- כפתורי ▲ / ▼ ליד כל קומה מזמינים את המעלית בכיוון המתאים.
- בצד ימין נמצאים עשרת כפתורי היעד בתוך המעלית.
- כפתור בצבע ענבר מציין בקשה שעדיין ממתינה לטיפול.
- תא המעלית נע בין הקומות, והדלתות שלו נפתחות ונסגרות.
- עמודת `WAIT TIME` מציגה זמן המתנה בפורמט `MM:SS` מאז הקריאה הראשונה,
  בנפרד לעלייה ולירידה לפי החצים בראש העמודה. לחיצות חוזרות אינן מאפסות
  את המונה. אחרי פתיחת הדלתות לשירות הקריאה מוצג שוב `—`.
- הקומה המדווחת וכיוון המעלית מוצגים בלוח התא; המיקום הרציף שלה מוצג
  בתחתית המסך. בזמן תנועה הקומה המדווחת היא האחרונה שעברנו.
- אזור CURRENT PLAN מציג את העצירות המתוכננות, ו-LIVE ACTIVITY מציג
  לחיצות, תנועה ושירות נוסעים.
- Reset simulation מחזיר את המעלית לקומה 1 ומוחק בקשות מהסימולציה בלבד.
- סגירת החלון מכבה את שני חוטי העבודה.

לבדיקה ראשונה: לחץ על עלייה בקומה 3. כשהמעלית מגיעה והדלתות נפתחות,
לחץ על 7 בלוח שבתוך המעלית. היא תסגור דלתות ותמשיך לקומה 7.
אפשר ללחוץ על כפתורים גם בזמן תנועה.

לבדיקת הרחבת איסוף: שלח את המעלית ל-7 והמתן שתהיה פנויה. לחץ על עלייה
בקומה 3 ומיד אחר כך על עלייה בקומה 1. המעלית תמשיך ל-1 ותאסוף את הקריאה
מקומה 3 בעלייה. כשהיא פותחת דלתות ב-3, בחר 6 בלוח התא. סדר השירות יהיה
1, 3 ואז 6. ההרחבה חלה כשאין בקשות פנימיות, לפני האיסוף הראשון, ובתנאי
שאין קריאה שכבר הגיעה לסף ההמתנה ושעדיין אפשר לשנות את העצירה.

## מבנה

| קובץ | אחריות |
| --- | --- |
| `hardware.py` | תנועה לפי זמן, דלתות, חיישנים ויישום ממשק החומרה |
| `app.py` | החלון, כפתורים, ציור התא ועדכון התצוגה |
| `tests/` | בדיקות סימולציה וחיבור לבקר |

הממשק פועל בחוט הראשי ומקדם את הסימולציה באמצעות `after` של Tkinter.
שני חוטי העבודה של הבקר נשארים כפי שהם: האזנה וקבלת החלטות. לא נוסף
חוט אנימציה. פקודות הבקר פועלות על נתוני הסימולציה המוגנים בנעילה;
הן אינן נוגעות ברכיבי Tkinter.

התנועה היא במהירות קבועה של קומה ב-0.7 שניות. פעולת דלתות אורכת
0.45 שניות, והבקר משאיר אותן פתוחות לשתי שניות. זו סימולציה חזותית:
אין מודל פיזיקלי של תאוצה, משקל או בלימה. עצירת ביניים חדשה דורשת לפחות
רבע קומה של מרחק; אחרת החומרה דוחה אותה והבקשה נשמרת בבקר להמשך.
גם בהרחבת יעד איסוף נדרש לפחות רבע קומה עד היעד המקורי, כדי שניתן יהיה
לבטל את העצירה בו. החומרה מאפשרת שינוי יעד באותו כיוון; הבקר מחליט אם
לקצר את הנסיעה לעצירת ביניים או להאריך אותה לצורך איסוף לפני שינוי כיוון.

הסימולטור משתמש באותו שעון מונוטוני כמו הבקר, ופקודות מקדמות את המיקום
לפני בדיקת עצירת ביניים. כך גם אחרי רענון מסך מאוחר לא מתקבלת עצירה
בקומה שהמעלית כבר עברה. דיווחי חציית קומות נשמרים לפי סדר גם בפריים ארוך.

## בדיקות

```powershell
py -m unittest discover -s elevator_simulator/tests -v
py -m unittest discover -s tests -v
```

בדיקות המודל אינן דורשות חלון גרפי. הסימולטור הוא תוספת אופציונלית;
הדגמת הבקר המקורית ממשיכה לפעול באמצעות `py -m elevator_controller`.
